# 02 — Parameterize the pod's public base URL

**Source PRD**: [../prd.md](../prd.md)
**Blocked by**: None — can start immediately. (Its end-to-end demo
uses the tunnel hostname from #01 when available, but the mechanism
is verifiable with any override value.)

## What to build

Make the smoke pod advertise a publicly reachable API base URL while
every other pod keeps today's local literal — so hosted-auth links
minted by the smoke pod carry a `notify_url` Unipile's cloud can
actually POST to (PRD user story 14).

Today `APP_URL` is hard-pinned in `devpod/compose.yml`:

```yaml
APP_URL: https://api-${DEVPOD_NAME}.${DEVPOD_PROJECT}.localhost
```

and the backend builds the hosted-auth callback from it —
`UnipileHandler.AuthURL` (`backend/internal/handler/unipile.go`)
sets `NotifyURL = strings.TrimRight(apiURL, "/") +
"/api/v1/webhooks/unipile"`, where `apiURL` is `os.Getenv("APP_URL")`
threaded through `NewUnipileHandler` in `backend/cmd/api/main.go`.
**No Go change is expected** — the work is compose/env plumbing:

- Change the pin to an interpolation with the current literal as
  default, e.g.
  `APP_URL: ${MAGIKLEAD_PUBLIC_API_URL:-https://api-${DEVPOD_NAME}.${DEVPOD_PROJECT}.localhost}`.
- Determine which channel the devpods CLI feeds docker-compose
  interpolation from (it already interpolates `DEVPOD_NAME` /
  `DEVPOD_PROJECT`; check whether `.devpod.env` is regenerated by
  `devpods up` — if it is, the override must live somewhere that
  survives re-up, e.g. the user-owned
  `~/.config/devpods/magiklead/` config or a devpod.yml knob).
  Document the chosen channel.
- Only the smoke worktree sets the override (to the #01 tunnel
  origin). `FRONTEND_URL` stays local everywhere: hosted-auth
  *redirects* run in the founder's browser on the laptop, so
  `.localhost` works for them; only the webhook callback needs
  public reachability.

CI is unaffected (`.github/workflows/e2e.yml` sets `APP_URL`
directly, no compose).

## Acceptance criteria

- [x] With no override set, `devpods up` + `devpods exec api printenv
      APP_URL` shows exactly today's literal — the mvp pod's behavior
      is byte-identical.
- [x] With the override set in the smoke worktree's channel, the api
      container sees `APP_URL` = the override origin, and a minted
      hosted-auth request carries `notify_url =
      <origin>/api/v1/webhooks/unipile` (verify via a handler unit
      test asserting NotifyURL construction from the configured base
      URL — extend `backend/internal/handler/unipile_test.go` if not
      already covered — plus a live `printenv` check in the pod).
- [x] The override survives a `devpods up` re-run (i.e. the chosen
      channel is not clobbered by regeneration).
- [x] CLAUDE.md's devpod section documents the override variable, its
      channel, and that only the smoke pod should set it.

## Modules touched

- `devpod/compose.yml` (api service `APP_URL` line).
- The per-worktree override channel (`.devpod.env` or
  `~/.config/devpods/magiklead/…` — decided during execution).
- `CLAUDE.md` (devpod docs).
- `backend/internal/handler/unipile_test.go` only if the NotifyURL
  assertion is missing.

## Test prior art

- Handler unit tests: `backend/internal/handler/unipile_test.go`
  (constructs `UnipileHandler` with explicit frontend/api URLs).
- The e2e suite must stay green untouched — it never goes through
  compose.

## Out of scope

- Creating the tunnel/hostname itself — issue #01.
- Registering webhooks at Unipile — issues #03/#06.
- Making `FRONTEND_URL` or `NEXT_PUBLIC_*` public — not needed (see
  above).
