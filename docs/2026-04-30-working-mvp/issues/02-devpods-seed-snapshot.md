# 02 — Devpods seed snapshot

**Type**: AFK
**Source PRD**: [../prd.md](../prd.md)
**Blocked by**: None — can start immediately

## What to build

Use the seed pipeline that already exists in `devpod/devpod.yml` and `devpod/seeds/regenerate.sh` to produce the canonical-fixture snapshot. Run `devpods seed regenerate` once. The artefacts land in the per-machine seeds dir at `~/.config/devpods/magiklead/seeds/` (devpods's `$SEEDS_DIR`), matching how magikshot and other devpods-using projects in this stack ship seeds — they are **not** committed to the repo, same as `.env.backend`. From then on, `devpods up` on a fresh database auto-replays the snapshot from that path, the 5-org / 20-person fixture appears for free, and `/leads` search returns rows on first visit.

This explicitly does **not** add any probe-and-seed step to the api entrypoint — the PRD picks the existing devpods mechanism over a custom runtime probe. It also does not modify devpods to read seeds from the repo — the per-machine convention is intentional.

## Acceptance criteria

- [x] `~/.config/devpods/magiklead/seeds/db.sql.gz` exists, generated by `devpods seed regenerate` (not hand-crafted).
- [x] `~/.config/devpods/magiklead/seeds/manifest.json` exists; its `migration_hash` matches a SHA-256 of all `backend/migrations/*.up.sql` concatenated (per `regenerate.sh`).
- [x] `devpods down --force && devpods up` lands on a database where `SELECT COUNT(*) FROM persons WHERE canonical_name LIKE '%(devpod-fixture)'` returns 20, with no manual `cmd/seed` invocation.
- [x] `devpod/compose.yml` api entrypoint is unchanged (still `go run ./cmd/migrate && exec air`).
- [x] `POST /api/v1/leads/search` for "VP Sales" returns rows on first visit to a fresh devpod.
- [x] The `db.sql.gz` size is sane (tens of KB ballpark — flag if it's unexpectedly large).
